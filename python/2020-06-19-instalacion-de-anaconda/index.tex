publicación académica mediante Quarto. Se explican paso a paso; la

configuración inicial con desactivación de auto-activación del entorno
base, integración acelerada mediante Mamba, configuración recomendada
del archivo .condarc, personalización del shell Fish, aliases útiles
para flujos de trabajo con múltiples blogs/proyectos, integración con
herramientas del sistema (Quarto, R y LaTeX) y resolución de problemas
frecuentes. El enfoque prioriza ligereza (\textasciitilde50 MB), control
total, reproducibilidad mediante environment.yml y máxima velocidad de
instalación/resolución de dependencias. }

\subsection{1. ¿Qué son Miniconda y
Anaconda?}\label{quuxe9-son-miniconda-y-anaconda}

\textbf{Conda} es el gestor de paquetes y entornos en el que se basan
tanto Miniconda como Anaconda Distribution. Existen dos formas oficiales
de obtenerlo:

\begin{itemize}
\item
  \textbf{Miniconda}: según la documentación oficial, es una instalación
  \textbf{mínima y gratuita} de Anaconda Distribution que incluye
  únicamente \texttt{conda}, Python, los paquetes de los que ambos
  dependen, y un pequeño número de paquetes adicionales útiles. Si se
  necesitan más paquetes, se usa el comando \texttt{conda\ install} para
  instalarlos desde miles de paquetes disponibles por defecto en el
  repositorio público de Anaconda, o desde otros canales como
  \texttt{conda-forge} o \texttt{bioconda}.
\item
  \textbf{Anaconda Distribution}: es la distribución completa, que
  incluye conda, Python, y \textbf{miles de paquetes preinstalados}
  orientados a ciencia de datos y machine learning (NumPy, pandas,
  Jupyter Notebook, scikit-learn, entre otros), además de
  \textbf{Anaconda Navigator}, una aplicación de escritorio para
  gestionar paquetes y entornos sin usar la línea de comandos.
\end{itemize}

Ambas instalan el mismo gestor \texttt{conda} por debajo; la diferencia
está en cuánto software adicional viene preinstalado de fábrica.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{2. ¿Cuál elegir: Miniconda o Anaconda
Distribution?}\label{cuuxe1l-elegir-miniconda-o-anaconda-distribution}

Esta es una pregunta que la propia documentación oficial de Anaconda
responde explícitamente en su página de comparación (``Choosing between
Anaconda Distribution and Miniconda''). A modo de resumen orientativo:

\begin{itemize}
\tightlist
\item
  \textbf{Miniconda} es preferible si se quiere mantener una huella de
  instalación pequeña, control total sobre qué paquetes se instalan, o
  se trabaja en un entorno con espacio en disco o ancho de banda
  limitado.
\item
  \textbf{Anaconda Distribution} es preferible si se quiere tener de
  inmediato, en un solo paso, Python junto con miles de paquetes de
  ciencia de datos ya instalados y verificados, además de una interfaz
  gráfica (Navigator) para quienes prefieren no usar la terminal.
\end{itemize}

Ambas opciones son válidas para Kubuntu, Arch Linux y Windows; esta guía
cubre la instalación de \textbf{ambas} en los tres sistemas.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{3. Nota importante sobre los Términos de Servicio de
Anaconda}\label{nota-importante-sobre-los-tuxe9rminos-de-servicio-de-anaconda}

Según la documentación oficial de conda, \textbf{tanto Miniconda como
Anaconda Distribution vienen preconfiguradas para usar el repositorio de
Anaconda} (Anaconda Repository), y instalar o usar paquetes desde ese
repositorio está sujeto a los \textbf{Términos de Servicio de Anaconda},
lo cual puede requerir una licencia comercial de pago según el caso.
Existen excepciones para individuos, universidades y empresas con menos
de 200 empleados (vigente desde septiembre de 2024).

\begin{quote}
\textbf{Relevante para tu contexto académico (UNSCH)}: como individuo
afiliado a una universidad, normalmente caes dentro de las excepciones
declaradas por Anaconda para uso académico/de investigación, pero se
recomienda revisar los términos vigentes y el documento oficial ``Update
on Anaconda's Terms of Service for Academia and Research'' antes de un
uso institucional o de gran escala, ya que estas políticas pueden
cambiar.
\end{quote}

Esta nota aplica por igual a Kubuntu, Arch Linux y Windows, ya que es
una condición del repositorio de paquetes de Anaconda, no del sistema
operativo.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{4. Verificación de integridad del instalador (todas las
plataformas)}\label{verificaciuxf3n-de-integridad-del-instalador-todas-las-plataformas}

La documentación oficial recomienda \textbf{verificar el hash SHA-256}
del instalador descargado antes de ejecutarlo, para confirmar que no fue
alterado ni corrompido durante la descarga. No se recomienda usar
verificación MD5, ya que SHA-256 es más seguro.

\subsubsection{4.1. Dónde obtener el hash
oficial}\label{duxf3nde-obtener-el-hash-oficial}

\begin{itemize}
\tightlist
\item
  Para Miniconda: visita \textbf{repo.anaconda.com/miniconda}, donde se
  lista el hash SHA-256 oficial correspondiente a cada instalador.
\item
  Para Anaconda Distribution: el hash se publica junto al archivo de
  descarga correspondiente en la documentación oficial de Anaconda.
\end{itemize}

\subsubsection{4.2. Verificación en Linux (Kubuntu y
Arch)}\label{verificaciuxf3n-en-linux-kubuntu-y-arch}

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{sha256sum}\NormalTok{ nombre{-}del{-}archivo.sh}
\end{Highlighting}
\end{Shaded}

Compara el valor mostrado con el hash oficial publicado. Si coinciden,
el instalador es seguro de usar.

\subsubsection{4.3. Verificación en
Windows}\label{verificaciuxf3n-en-windows}

Puedes usar la herramienta de verificación en línea de Microsoft, o
desde el símbolo del sistema (Command Prompt):

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{CertUtil }\AttributeTok{{-}hashfile}\NormalTok{ nombre}\AttributeTok{{-}del{-}archivo}\NormalTok{.exe SHA256}
\end{Highlighting}
\end{Shaded}

Compara el resultado con el hash oficial publicado para ese instalador.

\subsection{5. Instalación en Kubuntu / Ubuntu ---
Miniconda}\label{instalaciuxf3n-en-kubuntu-ubuntu-miniconda}

\subsubsection{5.1. Descargar el
instalador}\label{descargar-el-instalador}

Desde la documentación oficial de conda, el instalador de Miniconda para
Linux se descarga desde la página oficial de Miniconda
(docs.anaconda.com/miniconda) o directamente desde el repositorio de
archivos:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{wget}\NormalTok{ https://repo.anaconda.com/miniconda/Miniconda3{-}latest{-}Linux{-}x86\_64.sh}
\end{Highlighting}
\end{Shaded}

\begin{quote}
\textbf{Nota}: \texttt{Miniconda3-latest-Linux-x86\_64.sh} apunta
siempre a la versión más reciente disponible para arquitectura x86\_64
(la habitual en la mayoría de laptops y PCs de escritorio). Si tu
hardware usa otra arquitectura (por ejemplo ARM/aarch64), ajusta el
nombre del archivo según lo indicado en repo.anaconda.com/miniconda.
\end{quote}

\subsubsection{5.2. Verificar el hash
(recomendado)}\label{verificar-el-hash-recomendado}

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{sha256sum}\NormalTok{ Miniconda3{-}latest{-}Linux{-}x86\_64.sh}
\end{Highlighting}
\end{Shaded}

Compara contra el hash oficial publicado en repo.anaconda.com/miniconda.

\subsubsection{5.3. Ejecutar el
instalador}\label{ejecutar-el-instalador}

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{bash}\NormalTok{ Miniconda3{-}latest{-}Linux{-}x86\_64.sh}
\end{Highlighting}
\end{Shaded}

\subsubsection{5.4. Seguir las indicaciones del
instalador}\label{seguir-las-indicaciones-del-instalador}

El procedimiento documentado oficialmente es:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Presiona \texttt{Enter} para revisar el acuerdo de licencia.
\item
  Desplázate (barra espaciadora) hasta el final del acuerdo.
\item
  Escribe \texttt{yes} y presiona \texttt{Enter} para aceptar los
  términos.
\item
  Confirma o cambia la ruta de instalación (por defecto, algo como
  \texttt{/home/\textless{}usuario\textgreater{}/miniconda3}). Presiona
  \texttt{Enter} para aceptar la ruta por defecto, o escribe una ruta
  alternativa.
\item
  Al finalizar la instalación, el instalador preguntará si deseas
  \textbf{inicializar conda} (\texttt{conda\ init}). Se recomienda
  responder \texttt{yes}: esto modifica la configuración de tu shell
  (por ejemplo \texttt{\textasciitilde{}/.bashrc} o
  \texttt{\textasciitilde{}/.zshrc}) para que conda se inicialice

\end{Highlighting}
\end{Shaded}

Tras la instalación silenciosa, para inicializar conda manualmente:

\subsubsection{11.2. Modo silencioso en
Windows}\label{modo-silencioso-en-windows}

Se usa el argumento \texttt{/S}, con argumentos opcionales adicionales
(todos sensibles a mayúsculas/minúsculas):

\begin{itemize}
\tightlist
\item
  \texttt{/InstallationType={[}JustMe\textbar{}AllUsers{]}} --- por
  defecto \texttt{JustMe}.
\item
  \texttt{/AddToPath={[}0\textbar{}1{]}} --- por defecto \texttt{0}.
\item
  \texttt{/RegisterPython={[}0\textbar{}1{]}} --- si se registra como el

\item

\item
  \texttt{/D=\textless{}ruta\ de\ instalación\textgreater{}} --- debe
  ser el último argumento, sin comillas; obligatorio si se usa

\end{itemize}

\subsection{12. Verificación final de la
instalación}\label{verificaciuxf3n-final-de-la-instalaciuxf3n}

Independientemente del sistema operativo o de si instalaste Miniconda o
Anaconda, estos comandos confirman que la instalación fue exitosa:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{conda} \AttributeTok{{-}{-}version}
\ExtensionTok{conda}\NormalTok{ list}
\ExtensionTok{conda}\NormalTok{ info}
\end{Highlighting}
\end{Shaded}

\begin{itemize}
\tightlist
\item
  \texttt{conda\ -\/-version} muestra la versión instalada de conda.
\item
  \texttt{conda\ list} muestra los paquetes instalados en el entorno

\item

En la línea de comandos, deberías ver el prefijo \texttt{(base)} antes
del prompt habitual, indicando que el entorno base de conda está activo.

\subsection{16. Solución de problemas comunes de
instalación}\label{soluciuxf3n-de-problemas-comunes-de-instalaciuxf3n}

\subsubsection{\texorpdfstring{16.1. El comando \texttt{conda} no se
reconoce tras instalar
(Linux)}{16.1. El comando conda no se reconoce tras instalar (Linux)}}\label{el-comando-conda-no-se-reconoce-tras-instalar-linux}

Asegúrate de haber cerrado y vuelto a abrir la terminal después de la
instalación, para que los cambios en
\texttt{\textasciitilde{}/.bashrc}/\texttt{\textasciitilde{}/.zshrc}
surtan efecto. Si instalaste vía AUR en Arch, recuerda que la activación
de conda \textbf{no} es automática (ver sección 7.1): debes agregar
manualmente la línea de \texttt{source} correspondiente a tu archivo de
configuración de shell.

\subsubsection{\texorpdfstring{16.2. Error de OpenSSL /
\texttt{cryptography} al ejecutar \texttt{conda} (reportado
específicamente en Arch
Linux)}{16.2. Error de OpenSSL / cryptography al ejecutar conda (reportado específicamente en Arch Linux)}}\label{error-de-openssl-cryptography-al-ejecutar-conda-reportado-especuxedficamente-en-arch-linux}

Es un problema documentado en los comentarios oficiales del paquete
\texttt{miniconda3} en AUR, relacionado con la versión de OpenSSL del
sistema y el ``legacy provider'' de la librería \texttt{cryptography}.
La solución reportada por la comunidad es exportar la siguiente variable
de entorno (por ejemplo, agregándola a \texttt{/etc/profile.d/conda.sh}
o a tu \texttt{\textasciitilde{}/.zshrc}):

\begin{Shaded}
\begin{Highlighting}[]
\BuiltInTok{export} \VariableTok{CRYPTOGRAPHY\_OPENSSL\_NO\_LEGACY}\OperatorTok{=}\StringTok{\textquotesingle{}1\textquotesingle{}}
\end{Highlighting}
\end{Shaded}

\subsubsection{\texorpdfstring{16.3. Falla la actualización del paquete
\texttt{miniconda3} de
AUR}{16.3. Falla la actualización del paquete miniconda3 de AUR}}\label{falla-la-actualizaciuxf3n-del-paquete-miniconda3-de-aur}

Reportado en los comentarios oficiales del paquete: si una actualización
vía AUR falla a mitad de proceso, purgar los remanentes de la
instalación fallida y volver a intentar (o, si es urgente, reinstalar la
versión previa que funcionaba) suele resolver el problema. Recuerda
también el procedimiento de la sección 7.3 (comentar la línea de
activación de conda antes de actualizar).

\subsubsection{16.4. Anaconda Navigator no abre o muestra errores
gráficos
(Linux)}\label{anaconda-navigator-no-abre-o-muestra-errores-gruxe1ficos-linux}

Revisa la sección 6.5 (Kubuntu) o 8.4 (Arch) sobre dependencias de
sistema para interfaces gráficas (OpenGL, X11/XCB, ALSA). Esto es más
probable en instalaciones minimalistas o entornos sin un entorno de
escritorio completo.

\subsubsection{\texorpdfstring{16.5. Errores de permisos al instalar en
\texttt{/opt} (Arch, vía
AUR)}{16.5. Errores de permisos al instalar en /opt (Arch, vía AUR)}}\label{errores-de-permisos-al-instalar-en-opt-arch-vuxeda-aur}

Como se discute en los foros oficiales de Arch Linux (sección 8.2),
instalar en \texttt{/opt} requiere privilegios de root, lo cual puede
generar fricciones de permisos al gestionar entornos conda
posteriormente como usuario normal. La alternativa documentada por la
comunidad es instalar manualmente el script oficial directamente en tu
\texttt{\$HOME}, evitando \texttt{/opt} por completo.

\subsubsection{\texorpdfstring{16.6. Quiero usar conda con
\texttt{fish\ shell}, no
\texttt{zsh}/\texttt{bash}}{16.6. Quiero usar conda con fish shell, no zsh/bash}}\label{quiero-usar-conda-con-fish-shell-no-zshbash}

Aunque tu configuración habitual usa \texttt{zsh}, si en algún momento
necesitas integrarlo con \texttt{fish} (documentación oficial de conda
para Linux):

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{fish\_add\_path \textless{}ruta{-}de{-}instalación{-}conda\textgreater{}/condabin}
\NormalTok{conda init fish}
\end{Highlighting}
\end{Shaded}
